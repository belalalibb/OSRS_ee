# بروتوكول الاستئناف — نسخة 0.4 (GitHub عند توفر التفويض + حزم استعادة دائمة كاحتياطي)

«تابع» = استئناف أول مهمة مصرح بها غير مكتملة. فقد الاتصال ليس نجاحًا أوفشلًا.

## 0. الحقائق التي بُني عليها هذا البروتوكول (مثبتة 2026-10-23)

- مساحة العمل `/home/user/webapp` مُسحت **16 مرة** حتى 2026-10-23 مساءً؛ لا يُفترض بقاء أي ملف أو commit بين الردود.
- تفويض GitHub **متقطع**: نجح مرة (نشر الفرعين + PR #1 + تحقق من clone جديد) ثم أُبطل خلال دقائق؛ الجلسات التالية أعادت `No Valid GitHub Authorization Found`. المالك لا يستطيع إعادة التفويض عند كل مرحلة.
- SB-Git وAI Drive محجوبان: الـCLI يتطلب خطة مدفوعة/رصيد ≥500، و`/mnt/aidrive` مجلد محلي غير مركّب. التفاصيل في ADR-013.
- **المثبت عمليًا**: `git bundle` + SHA-256 → رفع إلى رابط ملف دائم → حذف الآثار المحلية → إعادة التنزيل → تطابق الهاش → استعادة الـcommit نفسه. هذه هي آلية الحفظ المعتمدة.

## 1. دورة الاستئناف (كل جلسة جديدة أو «تابع»)

1. افحص `/home/user/webapp`: `ls`، `git status/log/for-each-ref`. إذا وُجد عمل أحدث من آخر حزمة مسجلة، **احفظه أولًا** (bundle مؤقت) ولا تستبدله.
1-ب. **محاولة `setup_github_environment` واحدة فقط** في بداية الجلسة. (أ) نجاح → `git fetch origin`، قارن SHA الـremote لـ`genspark_ai_developer` بآخر حزمة في PROGRESS؛ الأحدث هو المصدر (الحزمة قد تتقدم على الـremote). إن كان المحلي/الحزمة أحدث والـremote سلفًا له → push عادي ثم تحديث PR #1. (ب) فشل → لا تكرار؛ تابع من الحزمة أدناه وسجّل «تفويض غير متاح هذه الجلسة».
2. نزّل **أحدث حزمة** المسجلة في `PROGRESS.md` (قسم «آخر حزمة استعادة») عبر أداة تنزيل الملفات. لا تعتمد على رابط أقدم إلا إذا فشل الأحدث، ووثّق ذلك.
3. تحقق قبل أي استخراج: SHA-256 للحزمة يطابق المسجل، `git bundle verify` ناجح، ولا مسارات absolute/`..`/symlink إن كان الأرشيف ZIP.
4. إذا كانت مساحة العمل فارغة: `git bundle unbundle` ثم `update-ref` للفروع ثم `restore`. إذا لم تكن فارغة: افحص الفروق قبل أي دمج؛ لا `reset --hard` ولا حذف تاريخ.
5. تأكد أن `HEAD` يساوي SHA المسجل، وأن `git fsck` نظيف، وأن بصمات الملفات في `evidence/` مطابقة.
6. شغّل اختبارات الشرائح المنجزة (`python3 -m unittest discover -s tests` عند وجودها) وسجّل النتيجة الفعلية قبل متابعة أي مهمة.
7. اقرأ `TASKS.md` وحدد أول مهمة غير مكتملة. لا تكرر عملًا مكتملًا ولا تعِد التدقيق.

## 2. دورة الشريحة (Definition of Done)

1. diff محدود لهدف واحد؛ لا `git add .` دون مراجعة المسارات والمحتوى.
2. اختبارات offline تمر فعليًا (لا network game/Telegram/AI؛ لا Java/عميل). PASS بلا artifact ليس PASS.
3. فحص أسرار محدود على الملفات المضافة (أنماط tokens/passwords) قبل الـcommit.
4. commit محلي على فرع `genspark_ai_developer` برسالة `type(scope): description`. `main` يبقى عند آخر أساس منشور/معتمد.
5. `git bundle create <name>.bundle --all` + `git bundle verify` + `sha256sum`.
6. رفع الحزمة إلى رابط ملف دائم. تسجيل **الرابط + SHA-256 للحزمة + SHA للـcommit + الفرع + تاريخ UTC** في `PROGRESS.md` **ثم** commit توثيقي صغير وحزمة جديدة تحتويه (الحزمة الأخيرة دائمًا تحتوي سجلها السابق؛ لا تضع بصمة الحزمة داخل نفسها).
7. تحديث `TASKS.md` بالحالة الفعلية، وأي قرار جديد في جدول ADR بـFOUNDATION.
8. في رد المحادثة: اذكر الرابط وSHA صراحة؛ المحادثة هي السجل الخارجي الوحيد الناجي من مسح الـsandbox.

## 3. GitHub وطلبات الدمج (PR)

- بيئة التنفيذ تشترط commit + PR لكل تعديل. **القيد غير قابل للتلبية حاليًا لسبب خارجي** (لا تفويض)، لا لقرار داخلي. المعالجة المعتمدة: الالتزام بالجزء الممكن (commits منظمة على فرع `genspark_ai_developer`)، وتسجيل الـPR كـ**مؤجل موثق** في `TASKS.md` (PUB-02)، ويُنفَّذ أول ما يتوفر التفويض: push للفرع ثم PR واحد إلى `main` يجمع الشرائح، دون force push.
- محاولة `setup_github_environment` واحدة في بداية كل جلسة (البند 1-ب)؛ لا تكرار بعد الفشل. لا توكن من المحادثة أبدًا. المفاتيح التي نُشرت في المحادثة تُعد مكشوفة ويجب إلغاؤها.
- عند عودة التفويض: فحص المستودع الحقيقي (refs/default branch/history/content) → حفظ أي عمل بعيد → push عادي → PR → تحقق من SHA البعيد والشجرة والمحتوى → تسجيل النتيجة. لا تدّعِ نجاح النشر قبل التحقق.

## 4. ثوابت لا تسقط

- storage/OS/auth قرارات صريحة (ADR-003/007/008) قبل الشرائح التي تفترضها؛ pure contracts لا تنتظرها.
- لا live accounts، لا GE/بيع/نقل/أفعال مالية، لا تشغيل متعدد/غير مراقب، لا AI بسلطة تنفيذ، لا spoofing/mutation أو anti-ban guarantee.
- V01–V08 تبقى REPORTED_UNVERIFIED حتى pinned source checks فعلية؛ T01–T35 NOT_RUN حتى يُنفَّذ اختبارها بدليل.
- نهاية كل جلسة تحدد: خطوة واحدة تالية، عائقًا واحدًا، ورابط آخر حزمة.
